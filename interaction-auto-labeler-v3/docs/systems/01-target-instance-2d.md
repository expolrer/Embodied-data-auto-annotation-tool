# S1 目标实例与二维视频跟踪系统

## 目标与边界

从“抓取红色玩具”这类目标描述出发，在同类物体很多、机器人和相机持续运动的情况下，找出
实际被交互的那个实例，并在头部视角和执行腕部视角中持续输出框、mask 与统一 track ID。
非执行腕部默认只作为一致性对照，不要求逐帧人工标注。

本系统回答“哪个物体、在哪里、是否可见”；不负责判断完整任务是否成功，也不单独生成自然语言。

## 输入与输出

必需输入：同步 RGB、时间轴、目标类别/颜色/形状/相对位置等描述。

增强输入：夹爪开合、关节/末端运动、对齐深度、任务指令、相机角色。

输出写入事件图的 `entities` 与 `observations`：

- 场景全部候选实例和稳定 `entity_id`。
- 每帧每视角的 `bbox_xyxy`、mask URI、可见性、遮挡和置信度。
- 实际交互实例、执行手、头部/腕部跨视角身份及证据分解。
- 跟踪漂移、身份切换、长遮挡和离画等风险区间。

## 处理链路

1. 使用目标描述在头部全场关键帧运行开放词汇检测，建立同类实例盘点。
2. 由夹爪闭合、末端减速、深度接近和共同运动寻找接触锚点。
3. 对锚点附近的所有候选计算接触、夹爪内区域、前后景深、共同运动和跨视角一致性分数。
4. 选择实际交互实例，使用 SAM2 从接触帧向前、向后传播 mask。
5. 将头部实例投影/匹配到执行腕部；三维条件不足时只输出软关联及较低置信度。
6. 对遮挡、漂移、同类歧义和置信度突降帧建立审核队列。

GroundingDINO、Florence-2 等负责候选，不应仅凭文本相似度决定同类物体中的动作目标；SAM2
负责传播，也不应在身份切换后继续无条件传播。

## 人工交互

自动处理前允许用户在任一视角点选/框选目标；自动处理后仅审核接触帧、低分片段和漂移帧。
一次人工纠错应能重置实例身份，并触发该锚点两侧的局部重跟踪，而不是要求用户逐帧重画。

## 对 VLA 的使用

- ACT：将框/mask/目标中心作为训练期辅助定位损失、ROI 对比损失或采样标签。
- π0.5/其他 VLA：将实体指代与视觉 token 对齐，或用 mask 做训练期特征池化/辅助 grounding。
- 任何使用后续帧确定的目标轨迹默认 `policy_input_allowed=false`，防止训练和部署输入不一致。

## 验收

核心指标为实际交互实例准确率、box AP、mask IoU/J&F、跟踪成功率、ID switch、遮挡恢复率和
每次交互人工耗时。金标必须覆盖同类多实例、快速腕部运动、长遮挡、反光/透明物体和离画重入。

当前复用 V1/V2 的候选、接触证据、双向跟踪与审核页面，成熟度为 Beta；大规模发布前仍需在
本机位数据上拟合可靠度并冻结 untouched gold set。
