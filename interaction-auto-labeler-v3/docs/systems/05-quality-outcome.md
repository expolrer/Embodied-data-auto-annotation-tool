# S5 任务结果与数据质量系统

## 目标与边界

为 episode/subtask/event 标注成功、失败和失败原因，同时检测会污染训练的数据异常。系统输出
可解释的质量门控，不用一个未经校准的总分掩盖具体问题。

## 标签体系

任务结果至少包括 `success`、`partial_success`、`failure`、`unknown`。失败类型建议采用可扩展层级：

- perception：目标识别错误、身份切换、严重遮挡。
- planning：顺序/手臂/目标区域错误。
- manipulation：未接触、抓空、滑落、碰撞、放置不稳。
- sensing：RGB/depth 丢帧、曝光、时间不同步、关节异常。
- recording：视频截断、重复帧、指令缺失、episode 边界错误。

## 输入与输出

输入为 S2 事件、RGB-D、机器人状态、任务指令和数据版本。输出为结果标签、失败原因、异常区间、
进度一致性、置信度、自动接收/复核/隔离决定及逐条 reason code。

## 处理链路

1. 先执行确定性数据审计：时间戳、帧率、shape、NaN、冻结帧、深度空洞、关节越界和模态长度。
2. 用事件图检查任务逻辑，例如 grasp 后是否共同运动、release 后目标是否停留在目的区域。
3. 用打乱帧顺序的 GVL probe 检查视觉语言模型是否真正理解进度，而非仅识别场景。
4. 对成功/失败使用领域模型或受约束 VLM，并保留视觉、状态和几何证据。
5. 将 raw score 经 untouched gold set 校准后再执行阈值门控。

## 人工交互

审核队列按错误严重度和训练风险排序。审核人看到的是原因、相关帧、曲线和模型证据，可修改
结果或失败类型；“不确定”是合法答案，应进入后续裁决而不是被强制改成成功/失败。

## 对 VLA 的使用

- 过滤损坏或指令不一致数据；失败数据可以保留用于 failure-aware learning，而非一律删除。
- 作为 value/progress/success 辅助目标，或构造成功与失败轨迹对比学习。
- 为评测集提供事件级成败和失败类型，定位策略退化发生在哪一阶段。

## 验收

报告成败 macro F1、各失败类型召回、异常 precision/recall、bad-sample escape rate、保留覆盖率和
选择性 risk-coverage 曲线。任何自动接收阈值都应由业务要求的最小 precision 反推。

当前异常检测、GVL probe、可靠度和质量门控骨架已实现；专用成败/失败原因模型尚待金标训练，
因此总体成熟度为 Alpha。
